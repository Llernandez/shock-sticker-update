# ShockSticker Rescue Kit — 설계 문서

**작성일:** 2026-09-27
**상태:** 승인 대기
**범위:** 컴패니언 툴킷 (원본 바이너리 불가침)
**스택:** Python 3.11+ 단일, PyInstaller 배포
**연재:** 리버싱 추리물 형식, 8편

---

## 1. 문제 정의

Shock Sticker는 Delphi 2007로 빌드된 한국산 스티커 메모 프로그램이다. 개발이 10년 이상
중단되었고 바이너리는 패킹되어 있다. 두 가지 증상이 보고되었다.

1. **"잘못된 포맷" 에러** — 기동 또는 메모 로드 시 발생
2. **데이터 유실** — 메모가 사라지고 불러오기가 실패 (대기업 관제실 환경, 24시간 가동)

원본을 고칠 수 없다는 전제에서, 데이터를 바깥에서 지키는 도구를 만든다.

---

## 2. 설계 원칙

1. **원본 불가침** — 툴킷은 원본 실행 파일과 설치 폴더에 어떤 쓰기도 하지 않는다.
2. **데이터 우선** — 모든 파괴적 동작은 백업 이후에만. 복구는 항상 사본에서.
3. **무지에서 출발** — `.ssk` 포맷은 미지수다. 관측 → 가설 → 통제 실험 → 확정 순서를
   지키고, 추측을 코드에 넣지 않는다.
4. **실패도 자산** — 기각된 가설은 지우지 않고 기록한다. 연재의 재료이자 후속 작업자의
   지도가 된다.

---

## 3. 유실 원인 가설

검증 대상. 코드를 쓰기 전에 실험으로 좁힌다.

| ID | 가설 | 근거 | 우선순위 |
|----|------|------|----------|
| **H5** | **UAC VirtualStore 리다이렉션** | `C:\Program Files (x86)` 하위에 설치 시 윈도우가 쓰기를 `%LOCALAPPDATA%\VirtualStore\...`로 몰래 우회. 저장은 성공한 것처럼 보이지만 읽기는 원래 경로를 봄 → "사라졌다"의 고전적 원인 | 최상 |
| **H1** | **비원자적 쓰기** | 저장 도중 강제 종료·정전 시 파일이 절반만 기록됨. 백업 세대가 없으면 영구 유실. 관제실은 강제 재부팅이 잦음 | 상 |
| **H2** | **인코딩 경계 붕괴** | Delphi 2007은 유니코드 이전. `AnsiString`(CP949) 기반이라 특정 문자·길이에서 바이트 카운트가 어긋나면 이후 레코드 오프셋이 전부 밀림 → 곧 "잘못된 포맷" | 상 |
| **H4** | **길이 필드 오버플로** | 메모 수나 본문 크기가 임계를 넘으면 16비트 필드 랩어라운드 | 중 |
| **H3** | **다중 인스턴스 경합** | 두 인스턴스가 같은 data 폴더에 동시 쓰기 | 중 |

H5는 특히 실행 가치가 높다. **지금 사라진 것처럼 보이는 메모가 VirtualStore에 그대로
살아 있을 수 있다.** `E:\ShockSticker` 이관이 이 경로를 근본적으로 끊는다.

## 4. 아키텍처

```
shocksticker-rescue/
├── ssk/
│   ├── probe.py        # 바이너리 관측 — 엔트로피, 반복 패턴, 문자열, 구조 추정
│   ├── format.py       # 확정된 .ssk 구조 정의 (2편부터 점진적으로 채워짐)
│   ├── reader.py       # 관대한 파서 — 손상을 허용하고 읽을 수 있는 만큼 읽음
│   ├── validate.py     # 무결성 검사 + 손상 유형 분류
│   ├── repair.py       # 복구 전략 (오프셋 재동기화, 레코드 절단 복원)
│   ├── backup.py       # 세대 백업 + 원자적 쓰기
│   └── export/
│       ├── markdown.py
│       └── json.py
├── cli.py              # sskctl 진입점
├── tests/fixtures/     # 합성 샘플만 (실제 업무 내용 금지)
└── docs/
    ├── format-spec.md  # 역공학 결과 스펙
    ├── evidence/       # hexdump, 로그 — 연재의 증거물
    └── deadends.md     # 기각된 가설 기록
```

### CLI 표면

| 명령 | 역할 |
|------|------|
| `sskctl probe <file>` | 포맷 관측 리포트 — hexdump, 엔트로피, 구조 추정 |
| `sskctl check <dir>` | 무결성 검사, 손상 유형 분류 |
| `sskctl dump <file>` | 해석 결과를 JSON으로 |
| `sskctl repair <file>` | 복구 시도 (항상 사본에, 원본은 그대로) |
| `sskctl export <dir> -f md` | Markdown 변환 |
| `sskctl watch <dir>` | 변경 감지 시 세대 백업 (상주) |

`probe`가 1급 명령인 이유: 포맷을 모르는 상태가 이 프로젝트의 출발점이고, 관측 도구가
먼저 있어야 나머지가 따라온다. 연재 2편의 주인공이기도 하다.

## 5. 연재 편성

각 편이 곧 작업 단계다. 편마다 하나의 수수께끼를 열고 닫는다.

### 공통 구조 (추리물 포맷)

1. **증상** — 관측된 현상
2. **용의자** — 가설들
3. **심문** — 검증 실험
4. **자백** — 밝혀진 것
5. **증거물** — 코드·산출물

---

**0편 · 사라진 메모를 찾아서**
관제실에서의 경험, "잘못된 포맷" 에러. `E:\ShockSticker`로의 이관과 VirtualStore 수색.
→ 산출물: 이관 완료, 잔존 데이터 회수 (H5 1차 검증)

**1편 · 봉인된 상자**
패킹된 Delphi 2007 바이너리 앞에서. PE 헤더, 패커 식별, Delphi 버전 지문.
"왜 소스를 고칠 수 없는가"의 기술적 근거를 세우고 우회로를 택한다.
→ 산출물: 없음(정찰편). 컴패니언 툴킷이 유일한 답인 이유를 확립

**2편 · 바이트를 읽다**
`.ssk` 포맷 역공학. hexdump와 엔트로피, 그리고 통제 실험 — 메모 하나 저장 후 diff,
한 글자 추가 후 diff. 구조가 드러난다.
→ 산출물: `probe.py`, `docs/format-spec.md` 초안

**3편 · 관대한 파서**
엄격 파싱은 깨진 파일 앞에서 무력하다. 손상을 허용하고 읽을 수 있는 만큼 읽는 파서.
손상 유형 분류 체계를 세운다.
→ 산출물: `reader.py`, `validate.py`, `sskctl check`

**4편 · 범인 찾기**
H1~H5 검증. 의도적으로 파일을 손상시켜 "잘못된 포맷"을 재현한다.
→ 산출물: 재현 케이스, `repair.py`

**5편 · 다시는 잃지 않게**
원자적 쓰기와 세대 백업. 변경 감지 상주 데몬.
→ 산출물: `backup.py`, `sskctl watch`

**6편 · 탈출구**
`.ssk` → Markdown. CP949 인코딩 처리, 서식 손실 최소화. 데이터를 이 프로그램 바깥으로
꺼낼 수 있게 되는 순간.
→ 산출물: `export/markdown.py`

**7편 · 버려진 것을 고치는 일에 대하여**
GitHub 공개, exe 빌드, 회고.
→ 산출물: v1.0 릴리스

## 6. 작업 중 기록 규칙

추리물로 쓰려면 증거가 남아 있어야 한다. 나중에 재구성할 수 없는 것들이다.

- 모든 hexdump와 오류 로그를 `docs/evidence/`에 타임스탬프로 저장
- 기각된 가설은 `docs/deadends.md`에 기록 — 삭제하지 않는다
- 커밋 메시지를 서사 단위로 작성 → `git log`가 그대로 목차가 된다
- 막힌 지점의 스크린샷·에러 메시지를 즉시 남긴다

---

## 7. 공개 시 주의

- **`.ssk` 샘플에 실제 업무 내용을 넣지 않는다.** 합성 샘플만 커밋한다.
- **원본 바이너리와 설치 파일은 재배포하지 않는다.** 저작권 문제. 리포에는 도구만 올린다.
- **관제실 경험은 일반화해서 쓴다.** 구체적인 회사명·시스템명·업무 내용은 빼고 기술적
  상황만 남긴다. 전 직장 관련 정보 노출은 실제 리스크다.
- 라이선스: MIT 또는 Apache-2.0 (도구 코드 한정)

## 8. 즉시 다음 액션 (로컬 세션에서)

이 클라우드 세션은 `E:\` 드라이브에 접근할 수 없다. 아래는 로컬에서 수행한다.

1. `E:\ShockSticker` 이관 완료 여부 확인
2. `%LOCALAPPDATA%\VirtualStore\Program Files (x86)\` 수색 — 잔존 데이터 회수 (H5)
3. `.ssk` 샘플 확보 — 정상 1개, 가능하면 손상 1개
4. 통제 실험용 샘플 생성 — 빈 메모 1개, 한 글자 메모, 한글 메모, 긴 메모
5. 리포 초기화 및 0편 집필 시작
